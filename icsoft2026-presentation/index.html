DRuntime Hooks: Lowering

// What you write:
a ~= b;

// What the compiler generates:
_d_arrayappendT(typeid(typeof(a)), cast(byte[])a, cast(byte[])b);

The compiler lowers high-level expressions into runtime library calls

Array ops, casting, allocation, comparison, ...

The TypeInfo Bottleneck

Runtime dispatch: type properties fetched via virtual calls, despite being known at compile time
No inlining: extern(C) linkage + separate static library
Type erasure: parameters are byte[] / void[], requiring unsafe casts

Hooks predate D's template system - designed without generics

The Fix: Templates

Compile-time resolution: type info deduced from template parameters
Inlining: template bodies can be inlined at call sites
Type safety: actual types preserved, no casts needed

+ only instantiated hooks are linked - smaller binaries

Before: Non-Template Hook

extern (C) void[] _d_arrayappendT(
        const TypeInfo ti, ref byte[] x, byte[] y)
{
    auto tinext = unqualify(ti.next);
    auto sizeelem = tinext.tsize;    // runtime lookup!

    _d_arrayappendcTX(ti, x, y.length);
    memcpy(x.ptr + length * sizeelem,
           y.ptr,
           y.length * sizeelem);

    __doPostblit(x.ptr + length * sizeelem,
                 y.length * sizeelem, tinext);
    return x;
}
extern(C): no inline byte[]: type erasure TypeInfo: runtime dispatch

After: Template Hook

ref Tarr _d_arrayappendT(Tarr : T[], T)
        (return ref scope Tarr x, scope Tarr y) @trusted
{
    auto length = x.length;
    _d_arrayappendcTX(x, y.length);

    static if (__traits(hasCopyConstructor, T)) {
        size_t i;
        try {
            for (i = 0; i < y.length; ++i)
                copyEmplace(y[i], x[length + i]);
        }
        catch (Exception o) { /* destroy in reverse */ throw o; }
    } else {
        if (y.length) {
            memcpy(&x[length], &y[0], y.length * T.sizeof);
            static if (__traits(hasPostblit, T))
                try __doPostblit(x[length .. $], i);
                catch (Exception o) { /* destroy in reverse */ throw o; }
        }
    }
    return x;
}
Tarr : T[] - real types static if - compile-time exception safety

Issue: alias this

alias this allows a struct to implicitly convert to one of its members:

struct Reb(T, U) {
    T original;
    U stripped;
    alias original this;
}
// Reb!(const(A), A) was passed
// instead of the expected const(A)
Fix: unalias the expression before type checks in expressionsem.d

Challenge: Cross-Module Linking

-preview=dip1000: experimental flag enabling scope and return-ref checking - allows stack allocation of certain arrays
Module A
compiled with -preview=dip1000
array on stack, no template instantiation
Module B
compiled without dip1000
assumes A already generated it
Undefined symbol at link time: neither module emitted the instantiation
Fix: Always emit template instances in the module that triggered the lowering

Results: GDC - The Weak Symbol Problem

GDC emits templates as weak symbols by default
- linker can substitute function body from another translation unit
- compiler cannot inline (One Definition Rule)

Fix: -fno-weak-templates - emit to COMDAT sections - inlining enabled
